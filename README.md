# Kaggle Demand Forecasting

Demand forecasting on a 100-series retail dataset (5 stores × 20 products, daily, 2022-01-01 to 2024-01-30), comparing StatsForecast (AutoARIMA, AutoETS, MSTL) and Prophet, plus SHAP-based feature importance via a LightGBM surrogate model.

## Repository Structure

```
├── solutionfile.ipynb      # Main analysis notebook — the actual code (Steps 0–14, see below)
├── demand_forecasting.csv  # Source dataset (76,000 rows, 16 columns)
├── PLAN.md                 # Modeling plan: dataset summary, models, pipeline, notebook step list
├── dataset_findings.md     # Verified facts about the CSV (columns, dates, splits, data quality)
├── pyproject.toml          # Poetry project config and dependencies
├── poetry.lock             # Locked dependency versions
├── requirements.txt        # Plain pip dependency list (alternative to Poetry)
├── .devcontainer/          # VS Code devcontainer config
├── .vscode/                # Editor settings
├── .idea/                  # PyCharm project files
├── .github/                # GitHub Spec Kit ("speckit") agent/prompt definitions
└── .specify/                # Spec Kit scaffolding: templates, extensions, workflow config
```

All the actual data science work lives in `solutionfile.ipynb`. Everything else is either input data, planning docs, or tooling config.

## Notebook (`solutionfile.ipynb`) Structure

The notebook is organized into 15 sequential steps:

| Step | Purpose |
|---|---|
| 0 | Install libraries |
| 1 | Imports |
| 2 | Load data, parse dates |
| 3 | EDA — shape, dtypes, nulls, duplicates, describe |
| 4 | EDA — visualizations (time series, epidemic periods, distributions, correlation) |
| 5 | Build feature groups and `unique_id` (`Store ID` + `Product ID`) |
| 6 | `ColumnTransformer` + `Pipeline` (fit on train, transform train + test) |
| 7 | Train/test split; build StatsForecast-format DataFrames |
| 8 | Fit StatsForecast models (AutoARIMA, AutoETS, MSTL), predict 14 days |
| 9 | Fit Prophet per series (100 series) with epidemic holidays + regressors |
| 10 | Evaluate MAPE, RMSE, MAE across all 4 models |
| 11 | Forecast visualization — sample series with all model predictions overlaid |
| 12 | Feature importance — LightGBM surrogate model + SHAP |
| 13 | Grouped feature importance — consolidate one-hot columns back into business features |
| 14 | Business-friendly SHAP interpretation — demand-unit impact tables and curves |

Train window: 2022-01-01 → 2024-01-16. Test window: 2024-01-17 → 2024-01-30 (14-day horizon, 1,400 rows). Hyperparameter tuning, cross-validation, and deployment are explicitly out of scope (see `PLAN.md`).

## Dataset (`demand_forecasting.csv`)

16 columns: `Date`, `Store ID`, `Product ID`, `Category`, `Region`, `Inventory Level`, `Units Sold`, `Units Ordered`, `Price`, `Discount`, `Weather Condition`, `Promotion`, `Competitor Pricing`, `Seasonality`, `Epidemic` (disruption flag), `Demand` (target). Full column-level detail and verified facts are in `dataset_findings.md`.

## Tooling / Scaffolding

The `.github/`, `.specify/` directories are generated by [GitHub Spec Kit](https://github.com/github/spec-kit) ("speckit") — they define slash-command-style agent prompts (`speckit.plan`, `speckit.tasks`, `speckit.implement`, etc.) used to drive spec-first AI-assisted development. `.specify/memory/constitution.md` is an unfilled template and not currently in use. These directories don't contain project logic — they're workflow tooling only.
